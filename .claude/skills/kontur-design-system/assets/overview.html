Логотипы

  • Список идентификаторов логотипов находится в каталоге `logos/v2`. Идентификатор — имя папки, например aegis.
  • Путь к обычному SVG строится как https://s.kontur.ru/common-v2/logos/v2/{id}/{id}-{size}.svg, например aegis-32.svg. Для тёмной темы или тёмного фона выбирай вариант {id}-{size}-dark.svg. Размеры и наличие вариантов проверяй в папке конкретного логотипа.
  • PNG-логотипы доступны только в размере 32 и плотности @2x: https://s.kontur.ru/common-v2/logos/v2/{id}/{id}-32@2x.png. Другие размеры и плотности PNG не предполагай. Для SVG проверяй доступные размеры и варианты в папке конкретного логотипа.
  • Не подменяй размер CSS, если он задан в исходном документе автора.
  • На акцентном или дополнительном цветном фоне перекрашивай логотип целиком в белый gray-100; исходный цветной SVG там не используй. Правило применения описано в color-rules.md.
  • Для демонстрации проверены варианты 32 px: Контур, УЦ, Экстерн, Фокус, Диадок, Толк, Закупки, Эгида и Недвижимость. Для каждого доступны обычный SVG и SVG -dark; соответствующие PNG-варианты 32@2x также проверены.

Таблица соответствия продукта, цветовой схемы и ID логотипа хранится в semantic-tokens.md; для бренда «Контур» — в привязке экосистемы. ID используются для построения пути к файлу по правилу выше.

Иконки продуктов

  • Файлы находятся в каталоге `icons-products` на s.kontur.ru. Для основного продукта ID иконки совпадает с ID его логотипа. Например, ID admin образует путь https://s.kontur.ru/common-v2/icons-products/admin/admin-16.svg.
  • Выбирай подтверждённый файл нужного типа, размера и формата в папке продукта. Набор файлов у разных продуктов может отличаться; размеры в примере admin не считай универсальными.
  • Для продуктовых расширений IconID берётся из справочника расширений, а не наследуется от основного продукта. Путь к символу расширения: https://s.kontur.ru/common-v2/icons-products/{IconID}/symbol/{IconID}-symbol-24.svg. Убедись, что этот файл есть на статике.
  • Сохраняй размер и тип исходного файла. Не создавай отсутствующий вариант масштабированием другого файла.

Интерфейсные иконки

Каталог содержит названия, идентификаторы, тематические группы и поисковые теги.

  • Подбирай иконку по смыслу через title, groupTitle и tags.
  • После выбора используй точный идентификатор name.
  • Размер и начертание иконки задаются в исходном документе автора. Сохраняй их при подборе файла и не меняй по своему усмотрению.
  • Каталог не подтверждает URL файла, формат, размер или цвет.

Контракт применения цветовых переменных к иконкам: color-rules.md.

Хранение, размеры и форматы

  • Метаданные интерфейсных иконок хранятся в актуальном JSON и локальной копии references/icons/icons-ui.json. Каталог содержит title, name, groupTitle и tags; это указатель для поиска, а не сами изображения.
  • Файлы иконок находятся на s.kontur.ru в папках вида common-v2/icons-ui/{цвет}/{name}/. По умолчанию выбирай SVG из папки `black`; известны также готовые красные и белые PNG. Наличие цвета проверяй для конкретной иконки.
  • В проверенном семействе файлов есть размеры 16, 20, 24, 32 и 64 px. Форматы: SVG, PNG и PNG @2x. Варианты начертания: light, regular, solid; состав вариантов зависит от размера и иконки.
  • Имя файла состоит из идентификатора, размера и начертания, например calculator-32-regular.svg. Точный путь и доступные варианты проверяй на статике перед использованием.

Иллюстрации · Объектные

Принцип

Тип «Объектные» — продуктовые иллюстрации из illustration-object. Выбирай сюжет по каталогу, цвет — по общей продуктовой схеме, а размер и вариант — по наличию файлов. Исследованный пример business-box изображает открытую коробку с двумя стрелками вверх.

Каталог и ID

Источник: illustrations.json. Локальная копия: illustrations.json; обновляется через scripts/update.py вместе с остальными каталогами.

Проверено 23 октября 2026 года: 132 уникальных ID в семи группах. JSON — массив объектов: name — точный ID для пути, title — название (может повторяться), groupTitle — группа, tags — русские и английские поисковые слова. Например, у коробки name: business-box, title: бизнес, groupTitle: Бизнес и торговля. Ищи по tags, title и groupTitle, а адрес формируй по name, сохраняя исходное написание.

Каталог содержит ID и поисковые описания; он не перечисляет размеры, цветовые папки, форматы и варианты фона. Наличие всех вариантов business-box не доказывает такой же набор для остальных ID: проверяй папку выбранного сюжета.

Цветовые схемы

ID цветов общие с другими типами ассетов. Используй таблицу «Продуктовые схемы» в semantic-tokens.md; не заводи отдельную палитру объектных иллюстраций. Подтверждённые папки в корне типа: red, orange, green, green-mint, blue, blue-dark, violet, purple.

blue — голубая схема, blue-dark — синяя. Суффикс файла dark обозначает вариант иллюстрации, а не ID цвета blue-dark. Схему выбирай по привязке продукта, а не по названию сюжета.

Хранение и варианты

Базовый адрес: https://s.kontur.ru/common-v2/visuals/products/illustration-object/.

  • Папка: {color-id}/{illustration-id}/.
  • SVG: {illustration-id}-{size}x{size}-{variant}.svg.
  • PNG: {illustration-id}-{size}x{size}-{variant}@2x.png (@ может быть закодирован как %40).
  • Проверенные размеры business-box: 64, 96, 128, 192, 256. SVG имеет соответствующие width, height и viewBox; PNG @2x вдвое больше: 128, 192, 256, 384, 512 пикселей на сторону. При размещении PNG учитывай логический размер из имени.
  • Варианты файлов: light, brand, dark. Это буквальные суффиксы статики: не заменяй их на primary, accent или secondary при составлении URL. Выбор по фону и особенности исходных цветов описаны в едином контракте цветов.
  • SVG и PNG имеют прозрачный фон. Подложку задаёт макет. Сохраняй пропорции и внутренние поля; размеры могут содержать различия в геометрии, поэтому выбирай готовый размер, когда он подходит.

Правила перекраски

Единый контракт применения переменных для цветовых схем, интерфейсных иконок и иллюстраций. Значения токенов и привязки продуктов хранятся в semantic-tokens.md, значения базовых цветов — в base-tokens.md.

Цветовые схемы

Общие правила

  • Итоговая схема складывается из общих переменных и переменных выбранной продуктовой или экосистемной схемы. Тему выбирай отдельно.
  • Акцентный и дополнительный акцентный цвета выбранной схемы не зависят от темы: при переключении светлой и тёмной темы сохраняй те же базовые токены.
  • Цвет интерфейсной иконки определяется схемой, темой и фоном по матрице ниже.
  • У иллюстраций три смысловых цвета меняются по режиму фона: Primary, Brand или Dark. Прежние названия остаются допустимыми псевдонимами.
  • Если режим фона нельзя определить, используй Primary (прежний «Светлый»). После выбора бренда замени исходные hex-цвета в SVG.
  • Для логотипов действуют отдельные правила ниже. Правил перекраски продуктовых иконок пока нет.

Сборка схемы

  1. Выбери продукт или бренд и найди его схему в таблицах привязок semantic-tokens.md. Затем выбери светлую или тёмную тему.
  2. Возьми общие переменные для выбранной темы и добавь переменные выбранной схемы. --k-color-product-accent получает акцентный базовый токен продукта, --k-color-product-secondary — дополнительный токен той же схемы; оба значения одинаковы в светлой и тёмной темах. В экосистемной схеме Контура --k-color-accent использует eco-gray-24. Четыре цветных акцента экосистемы доступны отдельно как --k-color-eco-accent-1…--k-color-eco-accent-4.
  3. Только для схемы Контура замени общие значения строками из таблицы «Переопределения общих цветов» для выбранной темы. Для остальных переменных оставь общие значения той же темы.
  4. Пустое значение темы не заполняй по аналогии с другой темой. Это ограничение относится к переменным с отдельными значениями по темам; акцентные цвета действуют в обеих темах по правилу выше. Если продукт отсутствует в каталоге, исходное правило HTML-системы ведёт к схеме «Контур».

Используй точное значение по имени базового токена. eco-gray-N и gray-N — разные палитры, даже если числа в названиях совпадают. У gray-64 и gray-68 подтверждённых значений пока нет; не применяй их.

Общие назначения: --k-color-page-bg — фон обычной страницы, --k-color-page-islands-bg — фон страницы с островами, --k-color-card-bg — фон карточки, --k-color-text и --k-color-text-secondary — основной и второстепенный текст, --k-color-border и --k-color-border-bold — обычная и усиленная границы. Значения бери из таблиц, не из этого описания.

Карточки

Продуктовая схема

В светлой и тёмной темах текст на обоих цветных фонах окрашивай в gray-100. Иконки окрашивай по цвету фона:

Это правило действует одинаково при переключении темы: акцентные цвета от неё не зависят. Для нейтральной карточки используй общие переменные выбранной темы и матрицу иконок ниже.

Логотипы

Варианты и перекраска

  • На светлом нейтральном фоне используй обычную версию логотипа. На тёмном нейтральном фоне используй файл с суффиксом -dark.svg, если он есть для выбранного логотипа и размера.
  • На фоне акцентного или дополнительного цвета логотип должен быть полностью белым: gray-100. Не размещай там исходный цветной вариант и не считай файл -dark.svg белой версией.
  • Для перекраски SVG можно использовать его как CSS-маску с фоном цвета gray-100 либо подготовить белый SVG с сохранением формы и прозрачных областей. Не меняй пропорции и состав знака.

Для других сочетаний схемы, темы и фона цвет иконки пока не задан. Акцентные и общие переменные доступны в обеих темах.

Для inline-SVG задай color: var(...) с выбранной переменной, а окрашиваемым элементам — fill: currentColor или stroke: currentColor. Для gray-100 используй значение базового токена из base-tokens.md. При использовании внешнего SVG как CSS-маски задай цвет фона маски выбранным значением. Матрицу иллюстраций к иконкам не применяй.

Готовые PNG-файлы из каталога имеют фиксированный цвет и не меняются от CSS-переменной. Для динамического переключения цвета используй перекрашиваемую inline-SVG иконку.

Иллюстрации

Продуктовая схема

В исходной иллюстрации различай три смысловых цвета: акцентный, дополнительный и белый. Для белого сразу используй базовый токен gray-100, без отдельной семантической переменной. Выбирай режим по фону непосредственного блока:

В светлой и тёмной темах акцентный и дополнительный цвета продукта остаются теми же. Иллюстрацию с исходными цветами перекрашивай по смысловым частям SVG, а не заменой всех одинаковых hex-значений без проверки роли элемента.

Экосистемная схема

Эта матрица относится к экосистемной схеме и её inline-SVG иллюстрациям. Для продуктовой схемы используй таблицу выше. Сначала определи фон блока. Новые и прежние названия обозначают одни и те же режимы:

  • Primary — прежний «Светлый»: белый, серый или другой нейтральный светлый фон.
  • Brand — прежний «Акцентный»: фон равен или визуально соответствует var(--k-color-accent).
  • Dark — прежний «Дополнительный брендовый»: фон равен или визуально соответствует var(--k-color-brand-secondary).

Три последних столбца обозначают исходные смысловые цвета в SVG.

Объектные исходники

Для illustration-object цветовая папка использует общий ID продуктовой схемы из semantic-tokens.md. Имена готовых файлов содержат суффиксы light, brand, dark; это варианты поверхности, а не ID темы или цветовой схемы. Форматы и ссылки — в справочнике объектных иллюстраций.

Для перекраски используй исходные SVG из папки red. В исходной палитре #FE4C4C — акцент (red-normal-100), #661E42 — дополнительный цвет (red-normal-0), белый — gray-100. Для целевой схемы бери соответствующие акцентный и дополнительный токены из semantic-tokens.md. Применяй простое соответствие по варианту:

Суффикс варианта сохраняй при перекраске; не применяй к этим готовым SVG общую матрицу для inline-иллюстраций из разделов выше. Фон выбирай отдельно по месту использования: нейтральный для light, акцентный цвет целевой схемы для brand, дополнительный цвет целевой схемы для dark.
