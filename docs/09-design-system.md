# Дизайн-система: принципы и требования

Документ фиксирует дизайн-логику как проверяемые правила — чтобы любое новое решение
можно было верифицировать без апелляции к "духу продукта".

---

## Позиционирование через дизайн

Мы делаем инструмент для родителя в состоянии стресса, а не lifestyle-приложение.
Каждое дизайн-решение проходит через три вопроса:

1. **Снижает ли это тревогу или повышает?**
2. **Можно ли показать это скептичной бабушке без стыда?** (credible expert look, не playful-cute)
3. **Как это выглядит в 3 часа ночи, одной рукой, при освещении колыбели?**

## Цветовая система

### Палитра

| Роль | Light | Dark | Почему |
|------|-------|------|--------|
| bg | `#FEFAF5` тёплый молочный | `#1A1614` тёплый угольный | Ночной режим без агрессии белого |
| surface | `#FFFFFF` / `#F6EFE6` | `#25201C` / `#2F2925` | Иерархия без теней |
| primary | `#E8876B` коралл | `#F4A588` | Действие — тёплое, не тревожное |
| secondary | `#8FAF99` шалфей | `#A5C4AD` | Спокойный период, всё ок |
| accent | `#E8B86B` амбер | `#F0C482` | Редко: варнинги, не ошибки |
| success | `#7BA68E` | `#8FB89E` | Чекмарки, спокойная неделя |
| error | `#D97878` | `#E09090` | Мягкий, не алармовый красный |

### Семантика цветов (обязательно к соблюдению)

- **Коралл (primary)** = "сейчас что-то происходит, нужно внимание"
- **Шалфей (secondary)** = "сейчас тихо, всё в порядке"
- **Амбер (accent)** = "обрати внимание, но не срочно"
- **Error** = только деструктивные действия (удалить, выйти), не для предупреждений

### Правило контраста (WCAG AA)

Все текстовые элементы должны иметь соотношение контраста ≥ 4.5:1 на своём фоне.

Известная проблема: `textMuted` на `bg` в тёмной теме (`#887E76` на `#1A1614`) ≈ 3.5:1 —
ниже нормы. Допустимо только для декоративных/неинформативных текстов (timestamps,
подписи к подписям). Для чего-либо несущего смысл — использовать `textSecondary`.

## Типографика

### Шрифтовое семейство

```
iOS:     ui-rounded   (SF Pro Rounded — теплее стандартного SF Pro)
Android: sans-serif   (Roboto)
Web:     system-ui
```

SF Pro Rounded — намеренный выбор: округлые формы читаются как дружелюбные, не клинические.
Это тонкое, но реальное отличие от WW и Huckleberry, которые используют стандартный системный шрифт.

## Иконки

- **Строго Ionicons outline** — никаких filled, никаких других библиотек без обсуждения
- **Размер:** 20px (inline), 22px (list items), 24px (navigation), 28px (featured)
- **Не 16px** — слишком мелко для ночного режима и эмоционального контекста
- **Не 32px+** — слишком давит, становится "кричащим"

## Отступы и радиусы

### Spacing

```
xs:   4   (внутренние gap, иконка-текст)
sm:   8   (gap между элементами одного уровня)
md:   12  (padding небольших компонентов)
lg:   16  (padding стандартных компонентов)
xl:   20  (горизонтальный padding экрана)
xxl:  24  (gap между секциями)
xxxl: 32  (крупные разрывы)
huge: 48  (нижний отступ скролла)
```

### Radius

```
sm:   8   (мелкие элементы: chips, inputs)
md:   12  (карточки среднего размера)
lg:   16  (основные карточки)
xl:   24  (hero-элементы)
pill: 999 (теги, кнопки-пилюли, FAB)
```

Правило: **никаких прямых углов (radius: 0) в UI-элементах.** Только для разделителей/линий.

---

## Тени

```
sm: shadowOpacity 0.06, radius 4, offset (0, 2), elevation 2   — едва заметные карточки
md: shadowOpacity 0.12, radius 8, offset (0, 4), elevation 4   — FAB, модальные элементы
lg: shadowOpacity 0.20, radius 16, offset (0, 8), elevation 8  — modal sheets (будущее)
```

Тени применяются только к элементам, "летящим" над контентом (FAB, bottom sheet).
Карточки на одном уровне с фоном используют border, не shadow.

## Компоновка экранов

### Иерархия элементов

Каждый экран содержит:
1. **Hero-секция** — label (caption, textSecondary) + title (title/hero, textPrimary). Ничего лишнего рядом.
2. **Контентные секции** — карточки с одним смысловым слоем каждая
3. **Единственная primary CTA** — максимум одна `Button variant=primary` в видимой области

### Лимит акцентов

В пределах одной видимой области (без скролла) — не более 2 элементов с акцентным цветом
(primary/secondary). Больше → визуальный шум → тревога.

### Пустые состояния

- Только текст + необязательная мягкая outline-иконка
- Тон: "можно начать" (не "у вас ничего нет")
- Никаких sad-face иллюстраций, broken-state иконок
- Примеры уже в `06-tone-of-voice.md`

### Деструктивные действия

- Цвет `error` (`#D97878`) — только для деструктивных: удалить, выйти
- Всегда требуют подтверждения (Alert / confirm)
- Никогда не primary CTA — только ghost или standalone кнопка

---

## Тёмная тема

- Основной фон `#1A1614` — коричневый, не серый подтон. Это намеренно.
- Поверхности `#25201C` / `#2F2925` — два уровня, чтобы без теней создавать иерархию
- Все цвета палитры в тёмной теме — высветленные, не инвертированные
- Никаких чисто-белых текстов: `textPrimary` в тёмной теме = `#F4EDE4` (кремовый)

---

## Антипаттерны (запрещено)

| Запрет | Причина |
|--------|---------|
| Градиентные фоны | Визуальный шум, ощущение дешевизны |
| Filled-иконки | Тяжелее, агрессивнее outline |
| Более 1 primary CTA на экране | Перегрузка выбором |
| Анимации < 150ms | Воспринимаются как резкий сигнал |
| Чисто белый (#FFFFFF) как фон экрана | Агрессивен ночью |
| Картинки/иллюстрации в playful-стиле | Снижает credibility ("детское приложение") |
| Размер иконок вне диапазона 20–28px | Или мелко ночью, или кричит |
| radius: 0 для UI-элементов | Клиническая геометричность |
| Текст с контрастом < 4.5:1 на несущих элементах | Плохо читается ночью |
| Красный цвет (#FF...) для чего угодно кроме error | Тревожный сигнал |
